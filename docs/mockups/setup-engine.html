Setup: where each part runs

What changed from the previous mockup

  • Built on the real Setup window (0.9.2, spm/0.9.2-cwd): its step rail, page title, cards and Cancel / Back / Next bottom right. No popups.
  • The choice sits in the existing System check step, as Linux already has it. Windows gets the same two cards; no new step.
  • One choice by default. "Customise" opens a row per part: SENTIENT server, PostgreSQL (TimescaleDB follows it), ClickHouse.
  • Every combination of part × place × database is listed below, per OS, with what Setup can offer and what the install code does today.
  • Each database card says where it will run. A choice that is not possible is greyed with its reason in an (i).

Where the choice goes: two options

A. A new step "Where to install"

Not recommended
Its own page with In the system / Docker, right before Database.
  • One more step and one more Next on every install.
  • Comes too late: System check and Location already depend on the choice (Docker or WSL 2 checks, volumes or folders). Both would have to be done again.
  • Linux's cards on System check would move, so Linux changes too.

B. Inside System check

Recommended
The two cards on top of System check, on Windows as on Linux; Customise for a part-by-part choice.
  • Fewer clicks: no new step. The default is already picked, so the common case costs nothing.
  • Fits the current flow: Linux already chooses here, and the checks below the cards run again for the choice.
  • The database step stays as it is and shows, per card, where that database will run.

Every combination

Three parts with a place of their own: the SENTIENT server, PostgreSQL and ClickHouse. TimescaleDB is a PostgreSQL extension and runs where PostgreSQL runs. 16 combinations per OS: 4 for PostgreSQL, 4 for PostgreSQL + TimescaleDB, 8 for PostgreSQL + ClickHouse. "Setup" says whether the screens can reach it; "Install today" whether the install code does it now.
