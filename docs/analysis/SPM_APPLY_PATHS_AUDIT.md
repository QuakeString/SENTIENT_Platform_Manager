# SPM apply paths audit

Date: 2026-11-21. Read-only code audit of branch `spm/apply-paths-audit`: nothing was built or run.

Scope: every Platform Manager action that changes or reads a Sentient Gateway or SENTIENT install. That covers gateway settings Apply, takeover and adopt, update and rollback, start, stop and restart, the gateway web page, ports, TLS files, backup schedule, repair, logs and move data. Each was checked for Docker (host and bridge network), native systemd and Windows service, both on this computer and on a server over SSH through the agent (`--job`).

Classes:
1. A setting is written where the program does not read it, or env overrides it.
2. A Docker change needs a port publish, a volume or a recreate, but only restarts or sets env.
3. Data or logs go to a path no volume keeps.
4. A read-back checks the config, not the real effect.
5. A failure ends as success, or silently.
6. A takeover, update or recreate copies or drops container spec fields.

## Known (already being fixed)

- `gateway_docker.rs` `take_over` (~811) copies the old env verbatim, so env `host`/`port`/`accessToken` override the config file. The Gateway page then locks the connection (`manager/gateway_settings.rs:334`) and cannot edit it.
- `gateway_docker.rs` `planned_spec` (~1043) turns the web page on through env but never publishes 8642 on a bridge network. The read-back (`gateway_settings.rs` `mismatches`/`apply` ~741/793) checks env and config, not the port.
- The gateway container writes `data.db` and its logs under `ST_GW_DATA_DIR=/sentient_gateway/data`, which no volume mounts on a taken-over container, so every recreate loses buffered data and logs.
- Logs Save wrote a read error into the file as if it were the log.

## Checked and fine

- Gateway Docker recreate (Apply, update): the env file is 0600, the token never goes on a command line, the old container waits under another name and comes back on failure, `stays_up` catches a restart loop (`gateway_docker.rs:1094-1187, 1225-1228`).
- `planned_spec` with `plan.env` cannot overwrite `ST_GW_UI`, `ST_GW_UI_LISTEN` or `RUST_LOG`: `overrides()` leaves them out (`gateway_settings.rs:239, 507-514`).
- Gateway Docker takeover keeps the old container until the new one is up and puts it back on failure. The compose service is commented out with a `.spm-bak` copy (`gateway_docker.rs:855-944`).
- Legacy gateway update: config backup volume, undo steps, waits for "connected to platform" (`gateway_legacy.rs:354-455`).
- SENTIENT Docker safe update and rollback: image kept as `:spm-previous`, dry run, PG snapshot, undo, `start_and_check` checks HTTP and Running (`docker_ops.rs:584-740, 859-917`). `pin_tag` writes the old compose file back on failure (`:811-836`).
- Settings Apply refuses an external compose file and re-applies the old settings when SENTIENT does not answer (`settings.rs:234-283`), apart from A3 and A6.
- Native Linux `control_stack` and Docker `control_stack` wait for an answer. The Docker one checks from outside on Windows (`native_linux.rs:1129-1158`, `distro.rs:1867-1890`).
- Move data: copy, verify, switch back, outcome marker for the remote caller (`distro/move_data.rs:966-1110`).
- SENTIENT compose takeover keeps the old containers renamed until the new stack answers, then restores them on failure (`distro/adopt.rs:822-871`), apart from A12.
- Local root jobs (`rootjob.rs:41-84`) use the exit code and stderr, so the gateway-branch stderr-only errors are surfaced locally. Only the remote path (A1) loses them.
- Remote gateway Apply passes the plan as a file without secrets and the page password on stdin (`remote_pages.rs:3203-3260`). Its outcome is subject to A1.
- Windows gateway installer: checksum check, secrets in a private folder, removed after the run (`gateway.rs:634-713`).

## Checked and fine (install paths)

- Fresh Docker installs publish PostgreSQL and ClickHouse on 127.0.0.1 only (`db_loopback: true`: `installer/mod.rs:1231`, `remote_install.rs:457`; compose `distro.rs:462, 515`), and SENTIENT's own five ports on every address. Volumes are pinned by name, and the app's files are kept in `sentient_data:/var/lib/sentient` with `REPORT_OUTPUT_DIR` and `VC_REPOS_PATH` under it (`distro.rs:429-430, 541`).
- Docker install: schema first with `compose run`, then `up -d`, then a wait of up to 10 minutes for HTTP with the container state every 15 s (`distro.rs:981-1023`). An earlier volume is checked and its role password synced before anything starts when the plan says Keep or Fresh (`:1056-1087`).
- The admin password hash reaches psql as base64 on stdin, so the `$` of argon2 survives the WSL shell (`distro.rs:1790-1794`).
- Native Windows PostgreSQL: initdb with `--auth=scram-sha-256` and the superuser password from a file, never argv (`native.rs:594-615`). psql gets the password through `PGPASSWORD` (`:256`). Old trust clusters are switched to passwords with a sign-in check and a way back (`:851-895`).
